- **이 문서로 할 수 있는 것:** 발표 슬라이드 12장과 Streamlit 화면 3탭을 바로 만들기 시작할 수 있어요. 들어갈 숫자, 그림, 시연 코일까지 다 적어 뒀어요.

> ✅ 숫자는 모두 **최종 모델**(ojs/force_model.py: GBDT, 단조 제약) 기준이에요. 모델 성능은 [오정수 인계 문서](../ojs/인계_모델_최적화.md), 최적화 숫자는 [run_all_coils.py](run_all_coils.py)로 전체 코일을 다시 돌린 값이에요.

## 1. 발표 핵심 메시지

**한 줄:** "생산 전에 압하 배분을 가상으로 시험하고, 하중이 치우친 코일을 찾아 바로잡는 시뮬레이터"

말할 것 세 가지:
1. **정확한 가상 공정:** 논문 물리식보다 AI(GBDT)가 오차를 약 64% 줄였어요(MAE 1.24 → 0.44 MN).
2. **현장은 평균적으로 이미 균형을 맞춰요.** 문제는 코일마다 병목 스탠드가 다르다는 거예요.
3. **치우친 코일을 찾아 추천해요.** 전체 코일의 약 12%는 최대 이용률이 5% 넘게 줄고, 일부는 최대 21%까지 줄어요.

**피해야 할 표현**

| 쓰지 말 것 | 대신 이렇게 |
|---|---|
| "하중을 크게 줄였다" | "치우친 코일에서 최대 이용률을 최대 X% 낮췄다" |
| "현장은 균형을 신경 쓰지 않는다" | "경험과 설정표 기반 배분을 코일마다 데이터로 보완한다" |
| "설비 한계를 넘지 않게" | "과거 최대 하중 대비 이용률" (실제 설비 정격 데이터가 없어요) |
| "R² 0.99로 거의 완벽" | 전체 R²보다 **스탠드별 R²와 MAE**를 앞에 내세우기 (아래 2-2 참고) |
| "신강종도 검토 가능" | "학습한 10개 강종 안에서 검토 가능, 신강종은 재학습 필요" |

### 2-2. 하중 예측 모델 성능

평가 방식: 같은 코일이 학습과 평가에 동시에 들어가지 않게 **코일 단위로 분할**했어요. 논문은 행 단위 무작위 분할이라, 우리 방식이 더 엄격해요.

**메인 성능표** (처음 보는 코일 20%를 평가 데이터로 사용, `GroupShuffleSplit` seed 42)

| 모델 | R² | MAE (MN) |
|---|---|---|
| 논문 물리식 M3 재현 (기준선) | 0.946 | 1.24 |
| MLP | 0.988 | 0.56 |
| **AI (GBDT, 단조 제약)** | **0.992** | **0.44** |

**스탠드별 R² (발표의 핵심 그래프)**

| 스탠드 | F1 | F2 | F3 | F4 | F5 |
|---|---|---|---|---|---|
| 논문 M3 | 0.82 | 0.80 | 0.79 | 0.80 | **0.38** |
| MLP | 0.96 | 0.96 | 0.95 | 0.95 | 0.91 |
| GBDT (단조 제약) | 0.97 | 0.97 | 0.97 | 0.96 | **0.94** |

출처: [../ojs/인계_모델_최적화.md](../ojs/인계_모델_최적화.md) 2번

- 그래프는 스탠드별 묶음 막대(회색 = 논문 M3, 파랑 = GBDT)를 추천해요. F5의 차이(0.38 → 0.94)를 강조하세요.
- **단조 제약:** "더 눌렀는데 하중이 줄어든다"는 물리적으로 틀린 예측을 막았어요. 위반 7.4% → 0%, 정확도 손실 MAE 0.03 MN. 제약이 없으면 최적화가 모델의 틀린 구간을 찾아가요. 10번 "신뢰성 장치" 슬라이드에 넣어 주세요.
- 전체 R²가 높게 나오는 이유: 스탠드 평균값만으로도 R²가 0.74예요. F1과 F5의 하중 차이가 커서예요. 그래서 전체 R²만 보여주면 과장처럼 보일 수 있어요.

**과적합 질문이 나오면 이렇게 답하세요** (아래 숫자는 1차 모델로 따로 검증한 값이에요)
- 학습 R² 0.993, 평가 R² 0.988이에요. 차이가 작아서 과적합이 아니에요.
- 학습과 평가 사이에 30코일 간격을 둬도 0.987로 같아요.
- 약점은 **처음 보는 강종**이에요. 한 강종을 통째로 빼고 학습하면 전체 R²가 0.93~0.97로 떨어지고, 스탠드별로는 더 많이 떨어져요. 그래서 시뮬레이터는 학습한 강종만 선택할 수 있게 막았어요.

### 2-3. 최적화 결과

조건: 강종·폭·F1 입측 두께·최종 두께는 그대로 두고, 스탠드별 압하율만 과거 운영 범위(1~99%) 안에서 바꿔요. 목표는 "최대 이용률 + 스탠드 간 이용률 편차" 최소화예요.

| 지표 | 값 (7,403코일) |
|---|---|
| 최대 이용률 감소율 중앙값 | 0.9% |
| 최대 이용률 감소율 평균 | 1.8% |
| 5% 이상 줄어드는 코일 | 865개 (11.7%) |
| 10% 이상 줄어드는 코일 | 328개 (4.4%) |
| 최대 감소율 | 21.4% |

- 정리된 7,533코일 중 130코일은 과거 운영 범위 안에서 최종 두께를 맞추는 배분이 없어서 빠졌어요.
- 코일별 결과 전체: [outputs/opt_all_coils.csv](outputs/opt_all_coils.csv) (스탠드별 현재·추천 압하율, 하중, 이용률)

- **이용률** = 하중 ÷ 그 스탠드의 과거 최대 하중(상위 0.5%). 화면과 발표에서 이 정의를 꼭 한 번 적어 주세요.
- 대부분 코일의 효과가 작은 건 현장이 이미 평균적으로 균형을 맞추고 있어서예요. 이건 약점이 아니라 **"데이터가 현장 운영을 그대로 재현한다"는 근거**로 말하면 돼요.

## 5. Streamlit 틀

### 모델·최적화 함수 (둘 다 완성)

모델을 앱에 끼우는 방법은 [오정수 인계 문서](../ojs/인계_모델_최적화.md) 1번에 있어요. 최적화는 아래처럼 쓰면 돼요.

```python
# khj/optimize.py
from optimize import load_data, limits_from_data, coil_from_data, optimize, final_gbdt_predictor, Coil
df = load_data()                        # 앱 시작 시 한 번
lim = limits_from_data(df)              # lim.red_lo, lim.red_hi (슬라이더 범위), lim.cap (이용률 기준), lim.grades
predict_fn = final_gbdt_predictor(df)   # 최종 GBDT, 학습 약 30초 → st.cache_resource로 한 번만
coil = coil_from_data(2744, df)         # 샘플 코일 불러오기, 또는 Coil(...)로 직접 입력
res = optimize(coil, predict_fn, lim)   # 코일당 약 0.2초
# res["current"], res["best"] 각각:
#   {"reductions": [5], "forces_MN": [5], "util": [5], "bottleneck": "F1", "score": ...}
# res["util_max_drop_pct"]: 최대 이용률 감소율 (%)
```

앱의 `predict_batch()`에 이미 하중 모델을 끼웠다면, 그 모델 함수를 `predict_fn` 자리에 그대로 넘겨도 돼요. 형식은 둘 다 "스탠드 단위 표 → 하중(MN) 배열"이에요.

### 화면 구성

**사이드바 (입력)**
- 강종 (Grade01~10 드롭다운, 그 외 입력 불가)
- 폭 (mm), 연주기 (S/N)
- F1 입측 두께, 목표 최종 두께 (mm)
- "샘플 코일 불러오기": 3장의 시연 코일(2744, 2599 등)을 선택하면 실제 조건이 자동으로 채워져요.

**탭 1. 시뮬레이터**
- F1~F5 압하율 슬라이더 5개. 슬라이더 범위 = `lim.red_lo` ~ `lim.red_hi`
- 최종 두께가 목표와 다르면 차이를 표시해요. 또는 F5를 자동으로 맞춰요.
- F1~F5 하중 막대그래프: 이용률 0.9 이상은 주황, 1.0 이상은 빨강
- 스탠드별 두께 감소 곡선 (입측 → F5 출측)
- 지표 카드 4개: 최대 하중 (MN), 최대 이용률, 스탠드 간 이용률 편차, 신뢰도 (범위 안 / 범위 밖)

**탭 2. 최적 조건 추천**
- "최적 조건 추천" 버튼 → `optimize()` 호출
- 현재 vs 추천 하중 막대를 나란히 (MN과 이용률 둘 다)
- 압하율 비교표 (F1~F5, 현재 / 추천)
- 개선 지표: 최대 이용률 −X%, 편차 −Y%, 병목 스탠드 F? → F?

**탭 3. 모델 근거**
- 성능 비교표 (논문 M3 / MLP / GBDT)
- 스탠드별 R² 막대그래프 (2-2의 표)
- 실제-예측 산점도 ([../ojs/figures/actual_vs_pred.png](../ojs/figures/actual_vs_pred.png))
- 데이터 범위와 한계 안내 문구

### 구현 팁
- 모델은 `st.cache_resource`로 한 번만 불러오세요.
- `optimize()`는 코일당 약 0.2초라 버튼 반응으로 충분해요.
- 색은 기본 회색 + 강조 하나(파랑)로 통일하고, 경고에만 주황·빨강을 쓰는 걸 추천해요. kdh 그림과 같은 색(파랑 `#2a78d6`, 주황 `#eb6834`)을 쓰면 발표 자료와 톤이 맞아요.

## 6. 시연 시나리오 (2분 버전)

1. 사이드바에서 "샘플 코일 불러오기" → **코일 2744** (Grade02, 폭 1,235 mm)
2. 탭 1: F1 막대가 가장 높은 걸 보여줘요(이용률 0.74, 27.1 MN). "현재 배분에서는 F1에 하중이 몰려 있습니다."
3. (선택) F1 압하율 슬라이더를 올려서 F1이 주황으로 바뀌는 걸 보여줘요. "배분을 바꾸면 하중이 즉시 바뀝니다."
4. 탭 2: "최적 조건 추천" 클릭 → 최대 이용률 0.74 → 0.61 (−18.5%), 최대 하중 27.1 → 20.7 MN
5. 마무리 멘트: "실제 라인을 세우지 않고, 생산 전에 1초 만에 검토할 수 있습니다."
6. (시간이 남으면) 코일 2599: "한계 직전(98%)인 코일도 86%까지 여유를 되찾습니다."
